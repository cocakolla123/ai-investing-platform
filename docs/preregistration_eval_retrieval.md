# Pre-registration — journal retrieval evaluation (Phase 2)

Written before any retriever is run against the labeled set. The queries and
relevance labels (`evals/retrieval/queries.jsonl`, `evals/retrieval/qrels.json`)
are generated by a fixed rule and committed in the same commit as this file;
retrieval runs happen only in a later commit.

## Corpus

`journal_entries` as of 2026-10-03: 166 entries (79 lessons, 34 reviews, 53
theses), all embedded with BAAI/bge-small-en-v1.5 (Phase 1). For a query at
`as_of = D`, the candidate pool is every entry with `created_at <= D 23:59:59
UTC`, never a hash-fallback row — the same two guards as production.

## Queries (sampling rule)

Source: the dossier-stage contexts persisted by the committee campaign run
`replay-63220a3a5e9a` (699 contexts, 2026-03-03 → 2026-08-14): the exact text
the committee analyst saw for one symbol on one day.

Eligible: a context whose pool holds at least one relevant entry (grade ≥ 1).
Two strata, sampled with `numpy.random.default_rng(20261003)`, at most 2
queries per symbol:

- **S (same-stock available):** the pool holds ≥ 1 grade-2 entry — 30 queries
  (all of them if fewer are eligible).
- **X (cross-stock only):** no grade-2 entry, ≥ 1 grade-1 entry — 30 queries.

## Relevance rule (graded, mechanical, applied before retrieval)

An entry's facts come from the decision experience it is linked to
(`refs.experience_id`); a thesis (unlinked) uses its own `symbols`.

- **2** — same symbol as the query.
- **1** — different symbol, same sector (experience sector vs the query's
  `instruments` sector) AND same market regime (the replay runs' persisted
  per-session regime at the entry's trade date and at the query date,
  nearest prior session).
- **0** — otherwise.

Known weaknesses, stated in advance: the regime was `risk_on` on 123 of 135
sessions, so grade 1 is close to "same sector"; sectors are today's
classification (not vintaged); 17 of 113 linked experiences have no sector
and can only ever be grade 2 or 0. Grade 2 favours lexical matching (the
ticker appears in both texts), which is why stratum X is reported separately.

## Methods (all parameters fixed here; nothing is tuned on the labels)

| method | how |
|---|---|
| keyword | BM25 (k1 = 1.2, b = 0.75) over entry text; query = full dossier text; lowercase alphanumeric tokens, scikit-learn English stop words removed |
| vector | pgvector cosine through `JournalRepository.search` (production guards); query = bge-small embedding of `"Represent this sentence for searching relevant passages: " + dossier text` (model truncates at 512 tokens) |
| hybrid | reciprocal rank fusion of keyword top-50 and vector top-50, k = 60 |
| production (reference) | today's live query, the template `"{SYM} investment thesis, lessons and post-trade reviews"`, vector |

Main setting: no symbol filter. Secondary setting (stratum S only): symbol
hard filter, as production applies it.

## Metrics

Recall@5 (grade ≥ 1 counts as relevant; denominator = all relevant in the
pool), nDCG@10 (gain 2^grade − 1), MRR (first grade ≥ 1), retrieval latency
p50/p95 (query embedding included for vector/hybrid; embedding time also
reported separately). Paired bootstrap (10,000 resamples of queries) 95% CI
for each pairwise nDCG@10 difference.

## Decision rule

Phase 2 informs Phase 3's design; it has no ship gate. A method is called
"better" only if its paired 95% CI on nDCG@10 excludes zero, per stratum. The
Phase 3 pre-registration will name which query form the "vector" and
"hybrid" arms use, citing these results — written after this phase reports.
